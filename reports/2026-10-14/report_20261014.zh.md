### 5. hyperframes 让 agent 写 HTML 直接渲染成视频

hyperframes 是一个开源项目，自我定位是“写 HTML、渲染视频”，并明确为 agent 场景而设计，即让 AI 输出自己最熟练的 HTML 结构，再由渲染器出帧。其 GitHub 社区数据为 stars 62,976、forks 5,650、open issues 277。它的思路是把视频生产中的“生成”环节部分转化为“渲染”环节，从而绕开扩散模型在时序一致性和精确排版上的不可控，让 agent 的输出可复现、可 diff、可单元测试。若这条路走通，视频工具链可能从关键帧工具走向代码编排、从模型直接出像素走向“LLM 写结构 + 渲染器出帧”的分工，HTML 也有机会成为多模态生成的通用接口层，而它首先冲击的是程序化视频工具链与 agent 工具生态这两个细分方向。

### 3. Retrieval Disagreement as a Signal: Diagnosing and Steering Multilingual Dense Embedders

多语言稠密检索器把所有语言放进同一个共享空间，好让提问无论用什么语言都能找到相关文档。这篇由4位作者完成的工作显示，同一个问题用不同语言提出会检索到差异显著的文档，而且这种分歧并非源于语言理解能力弱：每种语言单独表现都不错，候选排序也与其他语言一致，分歧只在语言共享同一索引时才出现。作者进一步定位机制——每种语言保留自己的排序，但在共享索引中它的正确答案被压低，被查询自身语言或英文的非相关文档埋没，具体取决于模型。为此他们提出 disagreement-guided steering：对每种语言，把其他语言一致认可的文档与该语言特异检索到的文档作对比，以两者表示之差作为该语言专属方向，在推理时加到该语言的查询上；与语言均值移除、子空间移除、逐语言旋转等基线相比，该方法最强地缓解同语言拥挤，召回率保持竞争力，并与更能保住排序质量的均值移除形成权衡。这意味着多语言检索的评测重心可能从追求语言无关的单一共享空间，转向显式度量并纠正跨语言分歧，受影响的主要是多语言 RAG、跨语言搜索与嵌入模型的评测与部署，纯单语场景则相对有限。
